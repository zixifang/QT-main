# 界面数据契约

给后续 agent 设计回测结果时用。行情窗口只读本文件规定的 JSON。计算放在 `algorithms/`，写完 JSON 后运行 `python -m gui`，不要改 `gui/` 来迁就一种新算法。

`schema_version` 固定为 `1`。比例用小数，`-0.0182` 表示 -1.82%。空值写 `null`，不要写 `NaN`。

## 运行

```powershell
python -m gui
```

窗口标题默认是「行情」。右上角模式是「行情」「指数增强」「因子测试」。

回测结果只供给「行情」。指数增强和因子测试不读 `outdata`。它们要求 `index.json` 的 `source` 是一个含 `{代码}.csv` 的目录；指数增强还要求该目录有 `NDX.csv`。不满足时模式会回到行情。新算法不要把结果写进这两个模式。

## 界面怎么读文件

`gui/outdata.py` 是行情数据的全部入口。

| 函数 | 行为 |
|---|---|
| `list_datasets()` | 按文件夹名排序，读取每个含 `index.json` 的 `outdata/<dataset_id>/` |
| `load_symbol(dataset, symbol)` | 读取 `outdata/<dataset_id>/{symbol}.json` |

启动后的顺序：

1. 列出数据集，填左上角下拉框。显示名用 `index.json` 的 `name`。
2. 读 `symbols`。若有 `benchmark.id` 且它不在 `symbols` 里，股票表第一行插入这个代码，并读取同名 JSON。
3. 用当前股票 JSON 的 `dates` 生成年份按钮。默认停在最后一年。
4. 扫描股票 JSON 的 `algorithms`。只显示至少一只股票里已经有结果的算法。名称和说明优先用 `index.json` 里的登记。顺序跟 `index.json` 的 `algorithms` 数组一致。
5. 按当前页绘图。换数据集、换股票、换算法、换年、换月、换展示方式，都只重新读取已有 JSON。

股票表两列数字：

- 整体涨跌：有 `return_index` 且与 `dates` 等长时用它，否则用 `close`。按年是该年最后一个值相对上一年最后一个值；该年之前没有点时，改用当年第一个值。按 10 年是期末相对 10 年前的最后一个点。
- 年末价格或期末价格：始终是原始 `close`，不用 `return_index`。

`return_index` 由算法写入。单日涨跌超过 50% 的收益应在写这列之前记 0，界面不会再处理拆股。

## 行情页

选中普通股票时右侧五页。选中的代码等于 `benchmark.id` 时，右侧只有两页。指数 JSON 再把 `kind` 写成 `"index"`，成交量纵轴才会标成「成交量」。

前三页和指数两页会按展示方式截取 `dates` 以及与之等长的数组。截取只影响图。买卖点日期不在当前窗口内就不再画。第三页的表不跟月份走，它按选中年份从全长净值里切。

| 页 | 股票 | 读哪些字段 |
|---|---|---|
| 1 原始数据 | 成分股 | `dates`、`close`、`volume` |
| 2 算法点位 | 成分股 | `close`；当前算法的 `buy_dates`、`sell_dates`、`indicator`。`params.oversold` 和 `params.overbought` 都是数字时才画两条水平线 |
| 3 统计指标 | 成分股 | 图用当前窗口的 `equity`、`benchmark_equity`，窗口内第一条非零净值缩放到 1。表按选中年份，用全长 `equity`、`benchmark_equity`、`position` |
| 4 全局统计 | 与选中股票无关 | `index.json` 里当前算法的 `years[<年份>]`。选中年没有这份数据时，改用已保存的最后一年 |
| 5 历史走势 | 与选中股票无关 | 优先读算法条目的 `history`（`dates`、`strategy`、`benchmark`、`holding`）。没有则读指数 JSON 里该算法的两条净值。再没有则用 `years` 的各年综合盈利率。按整体、按年、按月截取窗口 |
| 1 指数行情 | 指数 | `dates`、`close`、`volume` |
| 2 指数指标 | 指数 | 当前算法的 `equity`、`benchmark_equity`，以及下面「指数 JSON」里的区间统计 |

展示方式：

- 按年：只留选中年的日期。
- 按月：只留选中年、选中月。没有行情的月份按钮停用。
- 按 10 年：取数据末日往前 10 年，年份按钮停用。

第四页可以换年，月份和展示方式停用。第五页跟随「按整体展示」「按年展示」「按月展示」。有日度净值时，图是该窗口内从 0 起的累计涨跌，不是把各年收益连乘。没有 `holding` 时不画持有。指数这根线的图例用 `benchmark.name`，没有这个名字时写成「买入持有」。

第三页表格列：累计收益、年化收益、年化波动、夏普比率、最大回撤、卡玛比率、交易次数、胜率。`stats.benchmark.win_rate` 写 `null`。`params.fee` 是数字时，标题里显示为百分比。

第四页表格列：股票数、盈利占比、综合胜率、综合盈利率、收益中位数、平均年化、平均夏普、平均回撤、交易次数、跑赢。行是「策略」、`benchmark.name`（否则「买入持有」），有 `holding` 时再加「持有」。`count`、`median_return`、`profit_ratio` 为空时该格显示「—」。跑赢只在策略行显示，格式是 `beat_benchmark/count`。上方柱状图用 `symbols[].cumulative_return`，从低到高排列。

## 目录

```text
outdata/<dataset_id>/index.json
outdata/<dataset_id>/{SYMBOL}.json
outdata/<dataset_id>/{benchmark.id}.json    有指数时才需要
```

`dataset_id` 与文件夹名一致。`symbols` 的顺序就是股票表从上到下的顺序，不要把指数代码放进这个数组。每个代码都要有同名 JSON。

`source` 写成相对仓库根目录的行情目录，例如 `data/nasdaq100`。行情页不打开这些 CSV。它只决定切换到因子测试或指数增强时能否留下。

## index.json

```json
{
  "schema_version": 1,
  "dataset_id": "nasdaq-xbrl",
  "name": "纳斯达克XBRL",
  "source": "data/nasdaq100",
  "price_field": "close",
  "symbols": ["AAPL"],
  "benchmark": {"id": "NDX", "name": "纳斯达克指数"},
  "universe_note": "股票池的一句话限制",
  "algorithms": [
    {
      "id": "fscore",
      "name": "【F-Score】",
      "note": "算法规则，显示在算法列表下方",
      "years": {
        "2020": {
          "symbols": [
            {"symbol": "AAPL", "cumulative_return": 0.1, "benchmark_cumulative_return": 0.2}
          ],
          "strategy": {
            "count": 1,
            "winners": 1,
            "losers": 0,
            "profit_ratio": 1.0,
            "win_rate": 1.0,
            "cumulative_return": 0.1,
            "median_return": 0.1,
            "annualized_return": 0.1,
            "sharpe": 1.0,
            "max_drawdown": -0.05,
            "trades": 1,
            "beat_benchmark": 0
          },
          "benchmark": {
            "count": null,
            "winners": 0,
            "losers": 0,
            "profit_ratio": null,
            "win_rate": null,
            "cumulative_return": 0.2,
            "median_return": null,
            "annualized_return": 0.2,
            "sharpe": 1.0,
            "max_drawdown": -0.08,
            "trades": 0
          },
          "holding": {
            "count": 1,
            "winners": 1,
            "losers": 0,
            "profit_ratio": 1.0,
            "win_rate": null,
            "cumulative_return": 0.15,
            "median_return": 0.15,
            "annualized_return": 0.15,
            "sharpe": 0.8,
            "max_drawdown": -0.1,
            "trades": 0
          }
        }
      }
    }
  ]
}
```

没有指数时省略 `benchmark`。没有「持有」这一行时省略每年的 `holding`。RSI 数据集通常没有这两项，第四页就只有策略和买入持有。

这里的 `years` 是第四页和第五页的唯一数据源。它和指数 JSON 里的 `algorithms.<id>.years` 不是同一份结构，不要互相覆盖。

`symbols[].cumulative_return` 是柱状图和该股当年策略收益。`benchmark_cumulative_return` 要一并写上，供以后核对，当前柱状图不画它。

策略行的 `cumulative_return`、`annualized_return`、`sharpe`、`max_drawdown` 应与指数页同一条组合净值在该年的结果一致。`median_return`、`profit_ratio`、`count` 来自各股。指数行只填指数本身的四个路径指标，`count`、`profit_ratio`、`median_return` 留 `null`。持有行的 `cumulative_return` 是各股买入持有的等权平均，`median_return` 是中位数。

## 股票 JSON

数组长度都等于 `dates`。`dates` 为 `YYYY-MM-DD`，从早到晚，不重复。

```json
{
  "schema_version": 1,
  "dataset_id": "nasdaq-xbrl",
  "symbol": "AAPL",
  "price_field": "close",
  "dates": ["2020-01-02"],
  "open": [75.0],
  "high": [76.0],
  "low": [74.0],
  "close": [75.5],
  "volume": [1000000],
  "return_index": [1.0],
  "algorithms": {
    "fscore": {
      "id": "fscore",
      "name": "【F-Score】",
      "note": "与 index.json 同一句说明",
      "params": {"side": 0.1, "fee": 0.0, "execution": "open"},
      "indicator": [7.0],
      "signal": [0.0],
      "position": [0.0],
      "buy_dates": [],
      "sell_dates": [],
      "equity": [1.0],
      "benchmark_equity": [1.0],
      "stats": {
        "strategy": {
          "cumulative_return": 0.0,
          "annualized_return": 0.0,
          "volatility": 0.0,
          "sharpe": 0.0,
          "max_drawdown": 0.0,
          "calmar": 0.0,
          "trades": 0,
          "win_rate": 0.0
        },
        "benchmark": {
          "cumulative_return": 0.0,
          "annualized_return": 0.0,
          "volatility": 0.0,
          "sharpe": 0.0,
          "max_drawdown": 0.0,
          "calmar": 0.0,
          "trades": 0,
          "win_rate": null
        }
      }
    }
  }
}
```

| 字段 | 要求 |
|---|---|
| `close` | 原始价格。第一页和第二页都用它 |
| `volume` | 第一页下方柱 |
| `return_index` | 可省略。有则长度等于 `dates`，供左侧整体涨跌 |
| `indicator` | 第二页下方折线。没有值的日子写 `null` |
| `signal` | 信号日收盘后才知道的目标权重，还没换成第二天的成交 |
| `position` | 实际持仓。多头算法只写大于等于 0 的权重 |
| `buy_dates` / `sell_dates` | 必须是 `dates` 里的日期。买入是仓位从 0 变为正，卖出是从正回到 0 |
| `equity` | 这只股票自己的策略净值，起点为 1。不乘组合里的小权重 |
| `benchmark_equity` | 这只股票买入持有的净值 |
| `stats` | 全样本。第三页不再读这张表，改按选中年份从净值里切 |

同一算法 `id` 要出现在每只有行情的股票 JSON 里。只在指数 JSON 里登记、成分股里没有的算法，列表里不会出现。

追加算法时保留文件里已有的其他 `id`。同名 `id` 用新结果覆盖。

## 指数 JSON

文件名是 `{benchmark.id}.json`，例如 `NDX.json`。`symbols` 里不要包含它。

在股票 JSON 的字段之外增加：

| 字段 | 要求 |
|---|---|
| `kind` | `"index"` |
| `name` | 图例和表格列名，例如「纳斯达克指数」 |
| `universe_note` | 指数指标标题下的限制说明 |
| `algorithms.<id>.equity` | 组合净值，与 `dates` 等长 |
| `algorithms.<id>.benchmark_equity` | 指数买入持有净值 |
| `algorithms.<id>.stats` | 全样本。`strategy` 和 `benchmark` 都含 `cumulative_return`、`annualized_return`、`volatility`、`sharpe`、`max_drawdown`、`calmar`、`wealth_ratio`、`beta` |
| `algorithms.<id>.stats_10y` | 近 10 年的同一结构。按 10 年展示时用它，没有则退回 `stats` |
| `algorithms.<id>.stats_since_2021` | 只要求 `strategy.wealth_ratio` 和 `strategy.beta`。指数指标表最后两行读这里 |
| `algorithms.<id>.years` | 键是四位年份。值是该年的 `{"strategy": {...}, "benchmark": {...}}`，字段与 `stats` 相同 |

指数 JSON 的 `years.<年>` 只服务指数指标页。第四页、第五页读的是 `index.json` 里算法条目的 `years`。两份都要写，数值来自同一条组合日收益和同一条指数日收益。

指数 JSON 不需要 `indicator`、`signal`、`position`、买卖点。指数页不画它们。

## 实盘模拟

`python -m algorithms.paper_account` 读取已有 `position` 和 `close`，把一个数据集、一个算法收成一个 10 万美元整股账户，写到 `outdata/<dataset_id>/paper/<algorithm_id>.json`。不覆盖股票 JSON 里的研究净值。

| 字段 | 含义 |
|---|---|
| `capital` | 100000 |
| `fee_per_share` | 0.005，美元/股 |
| `benchmark_name` | 有指数时是指数名称，否则是「买入持有」 |
| `dates` / `nav` / `cash` / `benchmark_nav` | 同一长度。`nav` 是账户美元市值，界面不缩放到 1 |
| `symbols.<代码>.shares` | 每日持股，整数，长度等于 `dates` |
| `symbols.<代码>.value` | 该股当日市值 |
| `symbols.<代码>.buy_dates` / `sell_dates` | 股数增加、减少的日期 |
| `stats` | 全样本。`strategy` 和 `benchmark` 的字段与第三页表格相同 |
| `years.<年>` | 第四页、第五页和第三页表格。`strategy` / `benchmark` 另含 `count`、`profit_ratio`、`median_return`、`beat_benchmark`。`symbols[].cumulative_return` 是该股当年仍持有期间的市值涨跌 |

成交规则：持仓生效日按前一收盘价先卖后买。权重加总大于 1 时缩放到 1。现金不够时，买单同比例缩小。不做空、不融资。卖出所得当天可以再买。

## 新算法要写入的最小集合

1. `outdata/<dataset_id>/index.json`：数据集名称、`symbols`、可选 `benchmark`、算法 `id`/`name`/`note`，以及每年的全局统计。
2. 每只股票一份 JSON：行情数组、`return_index`、该算法的权重、买卖点、两条净值和全样本 `stats`。
3. 有指数时再写一份指数 JSON：组合净值、指数净值、全样本、近 10 年、2021 年以来和分年的路径统计。

写完后不要改 `gui/app.py`。打开 `python -m gui`，确认数据集名、算法名、五页或指数两页都能读到这些字段。
